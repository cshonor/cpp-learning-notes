# 6.1 结构的基本知识

## 本节讲什么

**`struct`** 把多个不同类型的成员**打包**成一种复合类型。访问用 `.` 与 `->`；理解**内存对齐（padding）**是读硬件寄存器、网络报文、UEFI 协议结构的门槛。

## 要点

### 定义与访问

```c
struct point {
    int x;
    int y;
};

struct point p;
p.x = 10;
p.y = 20;
```

- **`.`**：结构体变量访问成员
- **`->`**：结构体**指针**访问成员（见 6.4）
- 结构体变量可**初始化**：`struct point p = { 10, 20 };`
- 同类型结构体可**整体赋值/拷贝**：`p2 = p1;`（按成员复制，非指针深拷贝）

### 嵌套结构体

```c
struct rect {
    struct point pt;
    int size;
};
/* r.pt.x */
```

UEFI `EFI_MEMORY_DESCRIPTOR`、GOP 模式信息等均为多层嵌套 `struct`。

### 内存对齐（本章核心难点）

- 成员按声明顺序布局，但编译器插入 **padding** 使各成员地址满足对齐要求
- 典型规则（因 ABI 而异）：`int` 4 字节对齐，`double` 8 字节对齐；结构体总大小为**最大成员对齐值的整数倍**
- **`sizeof(struct)` ≥ 各成员 `sizeof` 之和**；解析二进制协议时必须按**规范偏移**而非想当然

```c
struct example {
    char c;    /* offset 0 */
    /* 3 bytes padding */
    int i;     /* offset 4 */
};             /* sizeof 常为 8，非 5 */
```

## 考点

- 手写结构体大小与 offsetof（面试）
- ELF 头、TCP 头、行情 FIX/SBE 字段对齐错误 → 静默 bug

## 与后续衔接

`#pragma pack`、`_Alignas`（C11）可改对齐，但跨平台 ABI 须谨慎；第 8 章 `stat` 等系统结构体直接依赖对齐规则。
