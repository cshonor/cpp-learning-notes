# 5.2 指针与函数参数

## 本节讲什么

C **只有值传递**（[1.8](../ch01-introduction/1.8-参数传值调用.md)、[4.1](../ch04-functions-and-program-structure/4.1-函数的基本知识.md)）。传指针给函数时，**复制的不是指针指向的那块数据**，而是 **指针里存的地址值**；函数通过 `*` 解引用，就能 **直接操作调用方变量的内存**，无需拷贝大段数据——HFT 里追求极致效率、避免内存拷贝开销的典型手段。

**前置**：[5.1 指针与地址](./5.1-指针与地址.md)（`&`、`*`、`int **`）、[1.8 传值调用](../ch01-introduction/1.8-参数传值调用.md)。

## 一、传值传递：拷贝的是什么？

| 传参方式 | 拷贝进形参的内容 | 能否改外部变量 |
|----------|------------------|----------------|
| `void f(int x)` | `x` 的 **整型副本** | ❌ 只改栈上副本 |
| `void f(int *px)` | **地址数值**（指针的副本） | ✅ 通过 `*px` 改所指对象 |
| `void f(int **ppx)` | 二级指针的地址副本 | ✅ 可改 **外部指针变量本身**（[5.1 §二](./5.1-指针与地址.md)） |

```
调用 swap(&a, &b) 时

  实参 &a ──拷贝地址值──→ 形参 px（px 是副本，但里面存的地址与 &a 相同）
                              │
                              └─ *px 访问的是外面 a 的内存，不是栈上另一份 int
```

**关键**：形参指针与实参指针 **不是同一个指针变量**（各在各自栈帧里），但 **指向同一对象**。

## 二、经典示例：`swap` 为什么必须传指针？

### 传 `int` 失败（1.8 反例）

```c
void swap_wrong(int x, int y)
{
    int t = x;
    x = y;
    y = t;    /* 只交换了形参副本 */
}

int a = 1, b = 2;
swap_wrong(a, b);   /* a 仍 1，b 仍 2 */
```

### 传 `int *` 成功

```c
void swap(int *px, int *py)
{
    int t = *px;
    *px = *py;
    *py = t;   /* 通过地址改外面的 a、b */
}

int a = 1, b = 2;
swap(&a, &b);   /* 把 a、b 的地址传进去 → a=2, b=1 */
```

| 调用写法 | 含义 |
|----------|------|
| `swap(&a, &b)` | `&a`、`&b` 是 **地址值**，作为实参 |
| 形参 `px`、`py` | 收到的是 **地址的副本** |
| `*px`、`*py` | 沿地址访问 **外面的 `a`、`b`** |

交换发生在 **原内存**，不是函数栈里多复制出来的 `int` 副本。

## 三、两层效果：改「所指」vs 改「指针本身」

```c
void demo(int *p)
{
    *p = 100;      /* ✅ 改 p 指向的对象（外面的 a） */
    p = NULL;      /* ❌ 只改形参 p 的副本，外面的指针不变 */
}

void set_null(int **pp)
{
    *pp = NULL;    /* ✅ 改外面的指针变量 */
}
```

| 操作 | 一级指针形参 `int *p` | 二级指针形参 `int **pp` |
|------|----------------------|-------------------------|
| `*p = val` | 改所指对象 | — |
| `p = &other` | 只改形参副本 | — |
| `*pp = new_ptr` | — | 改外部指针变量 |

> 口诀：**一级改数据，二级改指针**。

## 四、数组作参数：传的是首地址（易混预告）

数组名与指针 **不完全是同一概念**，但 **传给函数时** 行为与传指针几乎一样：

```c
void fill(int *buf, size_t n)   /* 等价 void fill(int buf[], size_t n) */
{
    for (size_t i = 0; i < n; i++)
        buf[i] = 0;
}

int arr[100];
fill(arr, 100);    /* arr 退化为 &arr[0]，只传地址，不传长度 100 */
```

| | 数组名 `arr` | 指针变量 `p` |
|---|-------------|-------------|
| 表达式中 | 多数情况 **退化为** 首元素地址 | 变量里存的就是地址 |
| `arr++` / `p++` | `arr` **不能** 自增（常量地址） | `p++` **可以** 移动指向 |
| `sizeof(arr)` | **整个数组** 字节数（如 400） | — |
| `sizeof(p)` | — | 指针宽度（64 位通常 8） |
| 传函数后 | **退化成指针**，**丢失长度信息** | 本来就只有地址 |

**HFT 经典踩坑**：函数签名写成 `void f(int buf[])`，内部 `sizeof(buf)` 得到的是 **8（指针大小）**，不是原数组长度——必须 **另传 `n`** 或约定结束标记。详见 [5.3 指针与数组](./5.3-指针与数组.md)。

## 五、工程场景

| 场景 | 指针传参用法 |
|------|-------------|
| **HFT 订单簿** | 传 `level *` 原地更新价位，避免拷贝整档深度 |
| **环形队列** | 传 `head`/`tail` 指针（或 `int **`）原地推进 |
| **内核** | `copy_to_user(user_buf, kbuf, len)` — 用户缓冲区指针 |
| **驱动** | `volatile uint32_t *reg` 读写 MMIO 寄存器 |
| **输出参数** | `int status, void **out` — `malloc` 结果写回 `*out` |

**为何 HFT 偏爱指针传参？**

1. **零拷贝**：只传 8 字节地址，不传 MB 级行情/订单块；
2. **原地更新**：策略、风控直接改共享结构；
3. **多返回值**：`void parse(const char *in, int *code, double *price)`。

代价：调用方必须保证 **指针合法、生命周期覆盖函数调用期**；内核还须校验用户态地址。

## 背诵要点（精简版）

```
C 只有值传递；传指针 = 拷贝地址值，不是拷贝所指数据
swap(&a,&b)：*px *py 改的是外面 a、b 的内存
一级 *p 改所指；二级 **pp 改外部指针本身
数组传函数 → 首地址退化，长度另传；sizeof(形参数组)=指针宽
HFT：指针传参 = 零拷贝 + 原地更新
```
