# ch18 ELF 二进制静态分析工具：nm / readelf / objdump

## 章节目标

掌握**不运行程序**，分析 Linux 二进制（`.o` / `.a` / `.so` / `.ko` / `vmlinux`）的能力。看懂 DPDK 库、内核模块二进制布局，区分静态分析 vs GDB 动态调试。

## 定位

这三个是 ELF 二进制分析工具，**不属于 C 语言源码编译**，是编译完成后直接分析产物：看符号、段、重定位、汇编。

> C 源码你看得到；但 DPDK、内核很多时候手里只有二进制，没有源码或不想翻巨大源码树，就靠这三个工具。

## 三者分工

| 工具 | 核心用途 | 主要看什么 | 典型对象 |
|------|----------|-----------|----------|
| **nm** | 符号表 | 函数、全局变量，哪些导出、未定义 | `.o` `.ko` `.so`；DPDK 导出 API、内核导出符号 |
| **readelf** | ELF 文件元信息 | 程序头、节、符号表、重定位、dynamic 段 | `vmlinux`、DPDK 共享库、内核模块 `.ko` |
| **objdump** | 反汇编 | 机器码→汇编；段内容、重定位 | 反汇编函数，看编译器真实输出 |

## 静态 vs 动态（核心边界）

| | 静态分析 | 动态调试 |
|---|---------|---------|
| **工具** | nm / readelf / objdump | GDB / crash |
| **程序状态** | 不用跑，分析磁盘上的文件 | 运行中 / 暂停 / core dump |
| **能看到** | 符号、ELF 结构、重定位、汇编 | 内存值、寄存器、栈、变量 |
| **看不到** | 运行时变量的值 | — |
