# 1.5 GDB 源码级调试

## 本节讲什么

**gdb** 断点、单步、看内存、backtrace、**core** —— 定位空指针/栈溢出。

## GDB 是什么

**GDB**（GNU Debugger）是 GNU 项目下的命令行程序调试器，主要用来调试 C/C++、汇编等编译型程序，在 Linux/Unix 环境用得最多。

> **GDB vs GDP**：GDB 是 GNU 调试器（程序员工具）；GDP 是国内生产总值（经济指标）。完全无关，别搞混。

## 能干什么

| 能力 | 说明 |
|------|------|
| 启动程序 | 可带上参数运行待调试程序 |
| 设置断点 | 程序跑到断点就暂停 |
| 单步执行 | 一条语句 / 一条汇编指令，观察程序怎么走 |
| 查看/修改内存 | 寄存器、变量、任意内存地址 |
| 崩溃分析 | 段错误 core dump，定位崩溃在哪一行 |
| attach 进程 | 调试正在运行的进程（不停机排查） |

## 要点

### 编译须 -g

```bash
gcc -g test.c -o test    # -g 把调试信息（DWARF）打进可执行文件
gdb ./test
```

不加 `-g`，gdb 看不到源码行号、变量名，只能看汇编。发布版用 `-O2` 仍可调试，但变量可能被优化掉。

### 基本流程

```bash
gcc -g -O0 -Wall main.c -o app
gdb ./app
```

```
(gdb) break main          # 在 main 函数打断点
(gdb) run [参数]           # 开始运行程序
(gdb) next                 # 下一行代码（跳过函数调用）
(gdb) step                 # 单步进入函数内部
(gdb) print p              # 打印变量 p 的值
(gdb) print *ptr           # 打印指针指向的值
(gdb) x/16xb &buf          # 16 字节十六进制查看内存
(gdb) disassemble main     # 反汇编 main 函数
(gdb) info registers       # 查看寄存器
(gdb) bt                   # 调用栈回溯
(gdb) quit                 # 退出 gdb
```

### n vs s 的区别

| 命令 | 行为 |
|------|------|
| `next` (n) | 下一行，**跳过**函数调用（函数内部不停） |
| `step` (s) | 下一行，**进入**函数内部（逐行执行被调函数） |

### core 转储

```bash
ulimit -c unlimited
./app    # 崩溃生成 core
gdb ./app core
(gdb) bt
```

### 常用命令速查

| 命令 | 简写 | 作用 |
|------|------|------|
| `break` | `b` | 设置断点 |
| `run` | `r` | 开始运行 |
| `next` | `n` | 单步跳过 |
| `step` | `s` | 单步进入 |
| `print` | `p` | 打印变量 |
| `examine` | `x` | 检查内存 |
| `backtrace` | `bt` | 栈回溯 |
| `info registers` | — | 查看寄存器 |
| `disassemble` | — | 反汇编 |
| `continue` | `c` | 继续运行到下一断点 |
| `quit` | `q` | 退出 gdb |

## HFT / 嵌入式视角

- **attach 热进程**：HFT 交易引擎不能停机，`gdb -p <PID>` attach 到运行中的进程，设断点排查后 `detach` 不杀进程。但注意 attach 会让目标进程瞬间停住（SIGSTOP），生产环境慎用。
- **core dump 是事故现场**：交易系统崩了，core 文件就是黑匣子。生产环境务必 `ulimit -c unlimited` + 配好 `core_pattern`。
- **嵌入式交叉调试**：板子上跑 `gdbserver`，主机跑 `arm-linux-gnueabihf-gdb`，通过网络/串口远程调试。`set sysroot` 指定目标板根文件系统。
- **-O2 下的调试**：HFT 生产代码通常 `-O2`，变量被优化进寄存器、内联展开，gdb 看到的行号可能跳跃。关键变量用 `volatile` 防优化，或单独编译热点文件用 `-O0 -g`。
- **内核级**：内核 panic 用 `kdump/vmcore` + `crash` 工具，思路与用户态 core dump 相同——加载镜像 + 符号表，在崩溃点 bt。
