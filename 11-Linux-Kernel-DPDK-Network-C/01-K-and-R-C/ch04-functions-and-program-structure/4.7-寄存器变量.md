# 4.7 寄存器变量

## 本节讲什么

**`register`** 建议编译器把变量放在 CPU **寄存器**而非内存，以加快访问。现代编译器大多自动寄存器分配，手写 `register` 已较少见，但读旧代码、理解「热变量」优化时会碰到。

## 要点

- 形式：`register int i;` 或 `register char c;`
- 仅是**建议**，编译器可忽略
- **不能对 `register` 变量取地址**（`&i` 非法）—— 因未必有内存地址
- 适合极短循环内的计数器、频繁使用的局部量
- 与 **`volatile`** 不同：`volatile` 禁止优化，语义相反

## 底层取舍

- **HFT / DPDK**：靠编译器 `-O3`、内联、热路径布局； rarely 依赖 `register` 关键字
- 真正瓶颈在缓存、分支、系统调用，而非手动 `register`

## 与后续衔接

了解即可；性能优化重点放在算法、内存局部性（第 5 章指针与数组）和避免不必要的外部可见性（`static`）。
